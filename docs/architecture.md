# Архитектура «Часов Сингулярности»

Проектный документ к ТЗ v1.0.

Принятые решения: [ADR-0001](adr/0001-stack.md) — стек, статика первой;
[ADR-0002](adr/0002-model-semantics.md) — три правки в ядро;
[ADR-0003](adr/0003-palette.md) — палитра. Разбор дефектов модели —
[model-review.md](model-review.md).

**V0 идёт без бэкенда.** Единственный серверный код — функция генерации
OG-картинок, не имеющая состояния. Всё, что требует хранилища (короткие ссылки,
голосование, живая лента, автоматическое смещение якоря), отложено до M4;
разделы ниже, помеченные `M4`, описывают целевое состояние, а не V0.

## 1. Структура и границы

```
packages/
  core/          расчётное ядро + кодек сценария. Ноль зависимостей, ноль DOM,
                 ноль сети, ноль Date.now()
  data/          конфиг модели (YAML), страновые данные (CSV), zod-схемы;
                 в M4 сюда же — парсеры источников
  i18n/          сообщения, форматтеры, правила множественного числа
  ui/            React-компоненты, дизайн-токены, графики
apps/
  web/           Astro: сайт, все страницы пререндерены
  og/            edge-функция: OG-картинки, без состояния
  ingest/        M4 — воркер сбора данных по расписанию
reference/
  prototype.html эталон формул
docs/
  adr/           архитектурные решения
  model.md       описание модели для людей: каждое допущение и его обоснование
  editorial.md   редакционная политика: красные линии из §1.3
```

**Правило импортов, проверяемое в CI:**

```
core  →  (ничего)
i18n  →  core (только типы)
data  →  core
ui    →  core, i18n
apps  →  всё
```

Проверяется двумя способами: `eslint-plugin-boundaries` на уровне правил и
отдельный шаг CI, который падает, если в `packages/core/package.json` появилось
непустое поле `dependencies`. Второе важнее первого: ядро должно исполняться в
браузере, в воркере и в тестах без единого полифилла.

## 2. Ядро

### 2.1 Публичный API

```ts
// packages/core/src/index.ts

/** Всё, что двигает пользователь. Ровно это кодируется в URL. */
export interface Assumptions {
  doublingDays: number;            // 60…300
  friction: number;                // 0,5…4,0
  targetMinutes: TargetMinutes;    // 480 | 2400 | 9600 | 115200
  reliability: 50 | 80;
  singularityPct: number;          // 10…95, шаг 5
  malicePct: number;               // 0…100
  alignFailPct: number;            // 0…100
  mitigationPct: number;           // 0…100
  dep0Pct: number;                 // 0…80
  tauYears: number;                // 2…40
  adaptWindowYears: number;        // 5…100
  triggers: ReadonlySet<TriggerId>;
  geopolitics: false | { weights: ComponentWeights };
}

/** Всё, что задано экспертно и живёт в репозитории под версией. */
export interface ModelConfig {
  version: string;                 // "1.0.0" — попадает в ключ кэша OG
  anchor: { at: number; horizonMinutes: number; sourceId: string };
  metrPoints: readonly MetrPoint[];
  functions: readonly Item[];
  industries: readonly Item[];
  tiers: readonly TierSpec[];      // ровно три
  triggers: readonly TriggerSpec[];
  presets: Readonly<Record<string, Assumptions>>;
  constants: ModelConstants;       // всё из §1.4 model-review.md
  tierSemantics: 'nested' | 'exact';   // по умолчанию nested, см. ADR-0002
}

export function computeModel(args: {
  assumptions: Assumptions;
  config: ModelConfig;
  now: number;                     // мс UTC. Обязателен. Date.now() внутри нет
}): ModelResult;

export interface ModelResult {
  effective: EffectiveParams;      // D, митигация, множители триггеров
  singularity: { date: number | null; passedShare: number; percentile: number };
  items: readonly ItemResult[];    // 30 строк, отсортированы по дате
  tiers: readonly TierResult[];    // кривая, медиана, P на 2035/2050/2100
  anyLevel: { curve: Curve; medianDate: number | null };  // при nested === tiers[0]
  expected: { deaths: number; usd: number; atYear: number };
  doomsday: { minutesToMidnight: number; alertLevel: AlertLevel };
  raceIndex: number | null;
}
```

Форматирования в `ModelResult` нет — только числа. Всё, что касается запятой как
десятичного разделителя, склонений и названий месяцев, живёт в `i18n`. Это
позволяет одному и тому же результату быть отрендеренным на сервере в OG-картинку
и на клиенте в две локали.

### 2.2 Вычисления в логарифмическом пространстве

Ядро не хранит горизонт — оно хранит `log₂H`. Обоснование и разбор переполнения:
[model-review.md §2.3](model-review.md).

```ts
const D = doublingDays * friction * triggerProduct;       // эффективное удвоение
const log2HAt   = (t: number) => LOG2_H0 + (t - T0) / (D * DAY);
const dateForL2 = (l2: number) => T0 + (l2 - LOG2_H0) * D * DAY;
```

Все потребители работают с логарифмом напрямую: логистика способности берёт
`log2HAt(t) − log2(порог)`, полоса прогресса — разность логарифмов,
дата достижения порога — `dateForL2(log2(порог))`. Возведение в степень
остаётся ровно в одном месте — подсказке графика.

### 2.3 Версионирование модели

Константы будут меняться: якорь METR сдвигается автоматически, коэффициенты
сложности — через pull request с обоснованием. Поэтому:

* `ModelConfig.version` — семантическая версия файла констант;
* мажорная часть меняется, если поменялась *формула* или семантика ступеней;
* минорная — если поменялись числа;
* версия попадает в ключ кэша OG-картинок и в подпись под каждым графиком;
* при смещении якоря в ленту публикуется элемент типа `anchor_shift` с
  посчитанным сдвигом в днях на базовом пресете.

Ссылка на сценарий кодирует **только допущения**, не конфиг. То есть числа по
старой ссылке со временем меняются — это и есть заявленная в ТЗ живая модель.
Но страница, открытая по ссылке, обязана показать пометку о том, что якорь с
момента создания ссылки сместился.

### 2.4 Кодек сценария

Живёт в `core`, потому что нужен и клиенту, и серверу (OG, короткие ссылки).

Формат: версия (1 байт) → фиксированный порядок квантованных полей → битовая
маска триггеров (2 байта) → опциональные веса стран (7 байт) → base64url.
Итого ~22 байта, ~30 символов в query. Помещается в любой мессенджер без
переносов.

Жёсткие правила:

* порядок полей неизменен внутри версии; новое поле = новая версия кодека;
* неизвестная версия — параметр игнорируется целиком и показывается уведомление;
  молчаливого частичного разбора не бывает;
* golden-вектора: закодированные строки пяти пресетов зафиксированы в тестах,
  чтобы ссылки на пресеты никогда не протухли;
* тест кругового преобразования: `decode(encode(x)) === x` для случайных
  допущений (fast-check).

Короткая ссылка: `slug = base32(sha256(байты сценария)[0..4])`, 8 символов.
Хеш, а не счётчик — значит `POST /api/scenario` идемпотентен и одинаковый
сценарий всегда даёт одну ссылку.

### 2.5 Тесты ядра

| Тип | Что проверяет |
|---|---|
| Golden, числовой | все 5 пресетов при `now = 2026-08-17T00:00:00Z`, допуск 1e-9 |
| Golden, отображаемый | те же пресеты, но отформатированные строки — строго посимвольно |
| Property (fast-check) | нет `NaN`/`Infinity` ни при каком сочетании ползунков |
| Property | `P` не убывает по годам и лежит в [0, 1] |
| Property | ↑ отказ контроля ⇒ глобальная дата не отодвигается |
| Property | ↑ митигация ⇒ ни одна дата не приближается |
| Единичный | `умысел = 0` и `отказ контроля = 0` ⇒ все `P` строго нули |
| Единичный | вложенность ступеней (при `tierSemantics: nested`) |
| Кодек | круговое преобразование + фиксированные вектора пресетов |

Про «побайтово» из ТЗ §2.7 и почему буквально это требование невыполнимо —
[model-review.md §2.4](model-review.md).

## 3. Данные: измеренное и предположенное

ТЗ §10.1 требует разделять их. Разделение проведено по хранилищу, по типу и по
внешнему виду:

| | Константы модели | Измеряемые данные |
|---|---|---|
| Где | `packages/data/config/*.yaml` | V0: `packages/data/datasets/*.csv` · M4: БД |
| Кто меняет | человек через pull request | V0: человек через pull request · M4: воркер |
| Как попадает в ядро | собирается в типизированный JSON на этапе сборки | так же; в M4 — из БД в SSR, с кэшем на клиенте |
| Как выглядит | пунктирное подчёркивание, метка «оценка» | сплошное, метка с датой сверки |

В V0 оба столбца физически лежат в репозитории, и это создаёт риск, что разница
между «измерено» и «придумано» сотрётся. Поэтому разделение проводится по типам
и по внешнему виду с самого начала, а не когда появится БД: `datasets/` и
`config/` имеют разные zod-схемы, и датасет без `source_url` на каждой строке
не проходит валидацию сборки.

YAML валидируется zod-схемой на сборке и превращается в модуль с типом
`ModelConfig`. Ядро при этом не знает про YAML и не умеет его читать — оно
принимает готовый объект. Границу это сохраняет.

### 3.1 Провенанс

Каждое число в интерфейсе несёт объект:

```ts
type Provenance =
  | { kind: 'measured'; sourceId: string; fetchedAt: number; url: string }
  | { kind: 'assumption'; rationaleAnchor: string }   // якорь в docs/model.md
  | { kind: 'derived'; from: readonly Provenance[] };
```

Рендерится компонентом `<Value>`: число + носитель провенанса (подсказка на
наведении, раскрытие по клику и по клавиатуре — на мобильном наведения нет).
`derived` показывает цепочку. Число без провенанса в этом сервисе не
компилируется: `<Value>` требует проп.

### 3.2 Датасеты V0

```
packages/data/datasets/
  metr-points.csv       модель, дата, горизонт, методика, CI, source_url, checked_at
  countries.csv         iso3, компонент, год, сырое значение, source_url, checked_at
```

Инвариант тот же, что будет в БД: **строка без `source_url` не проходит
валидацию.** Число без первоисточника в этом сервисе не существует.

Якорь модели в V0 — точка METR с максимальным горизонтом, вычисляемая из CSV на
сборке. Не «последняя по дате»: иначе регресс методики вроде перехода TH1 → TH1.1,
понизившего оценку GPT-4 на 35–57%, сдвинул бы якорь вниз и все прогнозы
разъехались бы от административного события. Смещение якоря в V0 — pull request;
механика та же, что будет в M4, ручной только спусковой крючок.

### 3.2a `M4` Схема БД

```
sources         id, name, url, kind, robots_ok, last_ok_at, last_error, cadence
raw_fetches     id, source_id, fetched_at, status, sha256, body (сжатое)
metr_points     id, model_name, measured_at, horizon_minutes, methodology,
                ci_low, ci_high, source_id, raw_fetch_id, is_anchor
incidents       id, external_id, occurred_at, severity, summary, url, source_id
market_quotes   id, platform, question_id, question_title, value, quoted_at, url
country_metrics country_iso3, component, year, raw_value, normalized, source_id
feed_items      id, kind, occurred_at, title, url, source_id, trigger_id,
                status(pending|published|rejected), classifier_note, published_at
scenarios       slug, payload, created_at, hits
trigger_votes   day_bucket, device_hash, trigger_id, value   -- уникальный ключ
```

Инвариант: в каждой таблице внешних данных обязателен `source_id`, и на него
есть внешний ключ. Число без первоисточника вставить нельзя физически.

### 3.3 `M4` Приём данных — предложение, а не перезапись

Главное правило воркера: **новые данные никогда не затирают хорошие данные
автоматически.**

```
запрос → сохранить raw → распарсить → санитарная проверка → 
    прошла  → published
    не прошла → pending + запись в лог + отметка на странице статуса
```

Санитарные проверки для METR: горизонт положителен, не более чем в 10 раз
отличается от предыдущего максимума, дата не в будущем, методика из известного
списка. Парсинг HTML-страницы METR по определению хрупок; сломанный парсер
обязан выдавать ошибку, а не тихо записать `NaN` в якорь модели.

При недоступности источника — показываем последнее известное значение с датой и
пометкой «данные устарели». Пустоты и ошибки на месте числа не бывает.

### 3.4 Честно про страновые метрики

ТЗ §7.1 записывает Stanford HAI, OECD.AI и Tortoise в автоматический сбор. В
реальности HAI AI Index — годовой PDF, Tortoise — публикация без API, OECD —
разрозненные выгрузки. Автоматизировать это нельзя даже с бэкендом, и
притворяться не надо: страновой рейтинг **навсегда остаётся ручным датасетом**,
с датой сверки на видном месте. Это не временное упрощение V0.

Приятное следствие: раздел рейтинга целиком, включая настраиваемые веса и индекс
гонки, работает на статике и попадает в V0 без бэкенда.

Автоматизации в M4 подлежат только источники с API: Metaculus, Manifold, arXiv,
AI Incident Database, Epoch AI. METR — парсинг страницы, самый хрупкий из всех.

### 3.5 `M4` Модерация ленты

Полноценная админка на V0 не нужна. Достаточно маршрута `/admin/queue`,
защищённого одним токеном из переменной окружения: список `pending`, кнопки
«опубликовать» и «отклонить», обязательное поле причины при отклонении.
Классификация LLM пишет `classifier_note` — это подсказка, помечаемая в
интерфейсе как предположение, и она никогда не меняет статус сама.

Триггер не включается автоматически ни при каких условиях. Опубликованный
элемент ленты лишь показывает рядом с триггером бейдж «возможно, произошло» со
ссылкой на первоисточник.

## 4. Клиент: состояние, производительность, тик

### 4.1 Одно состояние, две подписки

```
scenarioStore  (useSyncExternalStore, вне React)
   │  изменение допущения
   ▼
computeModel()  ──> modelStore ──> компоненты через селекторы
   
clockTicker (1 Гц) ──> только два счётчика и часы
```

Секундный тик **не пересчитывает модель**. В прототипе `tick()` дёргает те же
узлы, что и полный рендер; при переносе это обязано разойтись, иначе на
мобильном мы платим полный пересчёт каждую секунду при нулевой пользе.

### 4.2 Бюджет 16 мс

Объём работы на пересчёт: 30 элементов, 3 ступени × 75 лет = 225 итераций
простой арифметики. Это микросекунды. Узкое место — не расчёт, а перерисовка
двух SVG и тридцати строк с полосами.

Порядок действий: сначала измерить `performance.mark` вокруг `computeModel` и
вокруг коммита React, и только потом оптимизировать. Ожидаемое решение, если
понадобится: счётчики и подпись у ползунка обновляются синхронно, тяжёлые
списки — в `startTransition`. Web Worker — последнее средство, как и требует
ТЗ §13.

### 4.3 Рендер расчёта на сборке

Astro на этапе сборки вызывает `computeModel` для базового пресета и рендерит
те же React-компоненты в HTML, включая полностью нарисованные SVG. Пользователь
видит корректные числа и графики до загрузки JS; гидратация оживляет ползунки и
применяет сценарий из URL, если он там есть.

Отсюда деталь, которую легко упустить: страница, открытая по ссылке со
сценарием, сначала показывает базовый пресет и только потом перещёлкивается на
переданный. Чтобы это не выглядело сбоем, у пяти пресетов свои пререндеренные
страницы (они всё равно нужны для индексации по §13), а произвольный сценарий
на первом кадре показывает счётчики приглушёнными до гидратации.

Отсюда требование к компонентам графиков: никакого обращения к `window` и
`getBoundingClientRect` на этапе рендера. Геометрия — только `viewBox` и
проценты; координаты подсказки считаются из события, а не из размеров узла.

## 5. Графики и доступность

Оба графика переносятся из прототипа как React-компоненты, рендерящие SVG
строкой одинаково на сервере и клиенте.

Обязательный набор для каждого графика:

1. `role="img"` + `aria-labelledby` на заголовок и на скрытое текстовое резюме,
   генерируемое из данных («к 2050 году вероятность локального события 34%,
   регионального 12%, глобального 3%»);
2. **режим таблицы** — не в `details`, а переключателем «график / таблица», с
   тем же содержимым; таблица — настоящий `<table>` с `<th scope>`;
3. **клавиатурная подсказка**: график фокусируется, стрелки двигают вертикальный
   курсор по оси X, значения объявляются через `aria-live="polite"` в статусном
   элементе. Подсказка на наведении — частный случай того же механизма, а не
   отдельный код;
4. цвет закреплён за сущностью, а не за позицией: `tier.id → токен`, фильтрация
   не перекрашивает оставшиеся серии;
5. подписи текста — токенами текста, идентичность несёт плашка.

Порядковая шкала трёх ступеней — один тон, три равномерных шага светлоты, плюс
различающийся штрих (`2 5` / `7 4` / сплошная): `#3d6fae` / `#4a92e8` /
`#86b6ef`, обоснование в [ADR-0003](adr/0003-palette.md). Токены разделены на
`--text-*` и `--graphic-*` с разными порогами контраста, проверка — тестом в CI.

Поскольку ступени стали вложенными (ADR-0002), у графика накопленной
вероятности появляется обязательная подпись: каждая кривая — событие **этого
уровня или хуже**, поэтому нижняя всегда лежит выше верхней. Без этой строки
читатель решит, что 34% локального идут *вместо* 3% глобального, а не *включая*.

Отдельно: тикающие счётчики. Секунды не должны попадать в `aria-live` — иначе
скринридер зачитывает их бесконечно. Секундная часть получает `aria-hidden`,
а доступное имя счётчика — статичное («до сингулярности: 14 лет 212 дней»),
обновляемое раз в сутки. При `prefers-reduced-motion` отключается пульсация;
секундный тик при этом остаётся, но его стоит предложить выключить отдельным
переключателем — это движение, а не украшение.

## 6. Локализация

Русский и английский с первого дня, язык — префиксом пути (`/ru/…`, `/en/…`),
не по заголовку браузера: ссылка обязана вести туда, куда её отправили.

* числа и даты — `Intl.NumberFormat` / `Intl.DateTimeFormat` по локали;
* склонения — `Intl.PluralRules`, ни одного `if` по остатку от деления;
  в прототипе есть рукописная функция `plural` (стр. 632) — она заменяется;
* сообщения — плоские JSON-словари с ключами вида `tier.local.threshold`,
  типизированные так, что отсутствующий ключ не компилируется;
* тексты триггеров, сценариев и пояснений — часть продукта, машинный перевод
  запрещён; в CI проверка только на полноту ключей, не на качество;
* третий язык добавляется файлом словаря и записью в маршрутизации, без правок
  компонентов.

## 7. Публичный доступ к данным

### V0

Никакого динамического API нет и не нужно. Наружу торчат два адреса:

```
GET /og?s=<сценарий>          OG-картинка, чистая функция от параметров
GET /data/model.json          конфиг модели, точки METR, страновые данные
```

`model.json` — статический файл, собираемый из YAML и CSV на этапе сборки, с
`Cache-Control` и версией в имени. Это и есть «публичное API» V0: одна ссылка,
которую можно скачать, проверить и обсудить. Для сервиса, чья главная претензия
— открытость допущений, это честнее, чем документированный REST.

Расчёт модели наружу не выставляется — сознательно. Он весь на клиенте, конфиг
вкомпилирован в бандл, и сервис работает при полностью недоступной сети после
первой загрузки.

### `M4` Что добавится

`/api/metr/points`, `/api/countries`, `/api/feed`, `/api/markets`, `/feed.xml`,
`POST /api/scenario`, `GET /api/scenario/:slug`, `POST /api/vote` — read-only с
CORS, контракты из тех же zod-схем. Требование ТЗ §9.4 «сервис полностью
работает при отвалившемся бэкенде» к тому моменту уже выполнено по построению:
V0 бэкенда не имеет вовсе, и добавление API ничего не должно сломать при его
отказе. Данные из БД кэшируются в `localStorage` с датой и при недоступности
используются с пометкой «данные устарели».

Голосование, когда дойдёт до него: без учётных записей и cookies,
`device_hash = sha256(соль_дня ‖ IP ‖ User-Agent ‖ Accept-Language)`, соль
ротируется ежедневно. Один голос с устройства в сутки, никакого долгоживущего
идентификатора. Сырые строки удаляются через 30 дней, остаются агрегаты. В
интерфейсе прямо сказано, что защита слабая и число индикативное.

## 8. Наблюдаемость и прозрачность данных

В V0 страница `/status` показывает то, что есть: по каждому датасету — дата
последней ручной сверки, кто сверял (номер pull request), ссылка на
первоисточник, и явное «данные обновляются вручную». Это заметно менее
впечатляюще, чем живая лента, но зато не врёт.

Дата сверки обязана быть видна и на самих страницах с числами, а не только на
`/status`: ручное обновление тем честнее, чем виднее его давность.

`M4`: та же страница показывает по каждому источнику время опроса, результат,
число принятых записей и число ушедших в `pending`. Оповещение при
недоступности источника более суток — воркер, открывающий issue в GitHub. Логи
заданий в БД с ретенцией 90 дней, чтобы страница статуса не зависела от
внешнего сервиса логов.

## 9. План работ

Порядок из ТЗ §15 сохранён, но M4 вынесен за пределы V0, а страновой рейтинг
переехал вперёд — без бэкенда он оказался дешёвым (§3.4). Критерии приёмки
уточнены там, где допускали двойное чтение.

### V0

**M0 — каркас.** Монорепозиторий, два деплой-юнита (`web`, `og`), CI: типы,
линтер, границы импортов, тесты, проверка контраста токенов. ADR-0001…0003.
Пустой деплой с превью на PR.
*Готово, когда:* CI зелёный, превью на PR открывается, `packages/core`
собирается и имеет пустое поле `dependencies`.

**M1 — ядро.** Весь раздел 2 ТЗ с правками ADR-0002, кодек сценария, конфиг из
YAML, golden- и property-тесты. Затем первый экран: два счётчика, часы, пресеты,
оба набора ползунков.
*Готово, когда:* режим `tierSemantics: exact` воспроизводит прототип в пределах
допуска 1e-9 на всех пяти пресетах; режим `nested` даёт вложенные кривые;
property-тесты не находят `NaN` ни при каком сочетании ползунков; счётчик тикает,
не дёргается и не пересчитывает модель.
**Интерфейс не начинается, пока golden-тесты не зелёные.**

**M2 — графики и разбивки.** Два графика с режимом таблицы и клавиатурной
подсказкой, две таблицы-списка с раскрытием строки, карточки ступеней, панель
триггеров, блок математического ожидания, дисклеймер отдельным блоком в потоке.
*Готово, когда:* весь экран проходится с клавиатуры; axe не находит нарушений;
тест контраста зелёный; сборка отдаёт готовые SVG в HTML.

**M3 — шаринг.** Кодек в URL, OG-функция, режим сравнения `?a=&b=`.
*Готово, когда:* ссылка в чистом браузере воспроизводит сценарий точно;
предпросмотр корректен в Telegram, X и Slack; ключ кэша картинки включает
версию конфига.

**M5a — страны.** Датасет, рейтинг с сортировкой и разбивкой, настраиваемые
веса, кнопка «а как при других весах», индекс гонки, переключатель геополитики
(по умолчанию выключен) с пояснением, что коэффициент 0,4 — допущение автора.
*Готово, когда:* веса меняются и рейтинг пересортировывается; индекс гонки
влияет на митигацию только при включённом переключателе; у каждой ячейки есть
источник.

**M5b — локализация.** Английская версия, префиксы пути, `Intl.PluralRules`.
*Готово, когда:* обе локали полны, тексты вычитаны человеком, склонения
корректны в обеих.

### После V0

**M4 — живые данные.** БД, миграции, воркер сбора, санитарные проверки, лента с
модерацией, автоматическое смещение якоря, RSS. Плюс возвращаются короткие
ссылки и голосование по триггерам.
*Готово, когда:* сутки работы воркера без вмешательства; при выключенном
бэкенде фронтенд полностью функционален на закэшированных данных.

### Что писать параллельно с кодом, а не потом

`docs/model.md` — обоснование каждого коэффициента сложности и каждого лага. В
конфиге у каждой строки уже стоит поле `rationale` с якорем на раздел этого
файла; пустой якорь должен ронять сборку. Это единственный способ не оказаться
в конце M5 перед задачей «обосновать тридцать чисел, придуманных полгода назад».

`docs/editorial.md` — красные линии из §1.3 в виде проверяемого списка:
никаких персональных и геотаргетированных прогнозов, никаких названных
компаний и стран как виновников, механизмы без операционных деталей. Тексты
сценариев в карточках катастроф проходят по этому списку перед мержем.

# ADR-0003. Порядковая шкала ступеней и разделение токенов

**Статус:** принято 2026-08-17
**Контекст:** [model-review.md](../model-review.md) §3. Палитра прототипа
берётся целиком, кроме шкалы трёх ступеней риска.

## Проблема

Порядковая шкала прототипа `#184f95 / #3987e5 / #86b6ef` имеет два дефекта.

**Нижняя ступень не видна.** Контраст `#184f95` к фону карточки `#1a1a19` —
2,1 : 1 при требуемых WCAG 3 : 1 для графических элементов. Линия локального
риска толщиной 2 пикселя на почти чёрном фоне физически не читается. Критерий
приёмки M2 «проходит проверку контраста» при такой палитре невыполним.

**Шаги неравномерны.** В координатах светлоты CIE L\* шкала идёт 31 → 56 → 73:
первый шаг вдвое больше второго. Порядковая шкала должна читаться как
равномерная лестница, иначе глаз воспринимает две верхние ступени как пару, а
нижнюю — как чужеродную.

## Решение

```
--tier-local     #3d6fae      L* 46      контраст 3,4 : 1
--tier-regional  #4a92e8      L* 60      контраст 5,5 : 1
--tier-global    #86b6ef      L* 73      контраст 8,3 : 1
```

Шаги светлоты 13,5 и 13,0 — равномерная лестница. Все три проходят порог 3 : 1
для графики на `--surface-1`; на фоне страницы `--plane` запас ещё больше.
Тон единый (~212°), различие несёт только светлота, поэтому шкала переживает
любую форму цветовой слепоты. Второй канал различения — штрих (`2 5` / `7 4` /
сплошная) — сохраняется из прототипа.

`--series-1` остаётся `#3987e5`: график экстраполяции — одна серия, конфликта с
лестницей нет, а брендовый синий стоит сохранить.

## Второе решение: токены делятся на текстовые и графические

`--critical #d03b3b` даёт 3,6 : 1 — годится для рамки, точки и стрелки часов, но
не для текста, которому нужно 4,5 : 1. В прототипе он используется только как
графика, но ничто не мешает следующему разработчику поставить его в подпись.

Поэтому токены разделяются на две группы с разными гарантиями:

```
--text-critical   #e56a6a     5,5 : 1   можно в текст
--graphic-critical #d03b3b    3,6 : 1   только рамки, точки, штрихи
```

Проверенные значения остальных токенов на `--surface-1`: `--good` 5,2 : 1,
`--serious` 6,6 : 1, `--warning` 9,5 : 1, `--muted` 4,8 : 1 (проходит, но с
минимальным запасом — при любой правке пересчитать), `--ink-2` и `--ink` с
большим запасом.

## Проверка автоматическая, а не глазами

В CI добавляется тест, который читает файл токенов, считает контраст каждой
пары «токен × фон, на котором он разрешён» и падает при нарушении порога:
4,5 : 1 для группы `--text-*`, 3 : 1 для `--graphic-*`. Это дешевле, чем строчка
в чек-листе ревьюера, и не забывается.

## Последствия

* Одно расхождение с ТЗ §11.1, где палитра приведена как проверенная. ТЗ
  правится: проверку она в части нижней ступени не проходит.
* Значения `#3d6fae` и `#4a92e8` получены расчётом и должны быть подтверждены в
  контраст-чекере на реальной вёрстке до закрытия M2 — цифры выше посчитаны для
  сплошной заливки, а тонкая линия субъективно читается хуже.

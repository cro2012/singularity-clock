# ADR-0006. Опорная точка METR выбирается, а не зашита

**Статус:** принято 2026-08-19
**Контекст:** внешнее ревью, пункт «METR anchor всё-таки надо обновить»

## Проблема

Якорь лежал в конфиге одной строкой:

```yaml
anchor:
  at: "2025-11-24T00:00:00Z"
  horizonMinutes: 320
  model: "Claude Opus 4.5"
```

Три беды сразу.

**Число не сходилось с источником.** METR в срезе TH1.1 даёт для Claude
Opus 4.5 не 320 минут, а 293,0. Откуда взялись 320, восстановить не удалось —
скорее всего, округление от руки при переносе из прототипа. То же и с
остальными точками в `metrPoints`: там лежала смесь методик TH1 и TH1.1 с
пометкой `approx: true`, то есть единственное измерение во всей модели было
пересказано по памяти.

**Точка устаревала молча.** На 8 мая 2026 года METR опубликовал шесть замеров
после Opus 4.5. Сайт продолжал считать от позапрошлого, и узнать об этом
из интерфейса было нельзя: ни даты среза, ни ссылки, ни признака свежести.

**Выбор точки был спрятан.** Какой именно замер брать за основу — вопрос
спорный: свежайший фронтир у METR лежит выше шестнадцати часов, а METR прямо
пишет, что за такие измерения нынешний набор задач не ручается. Сервис,
построенный на идее «двигай допущения и смотри», прятал это решение в конфиг.

## Решение

Список якорей вместо одного, выбор — часть сценария.

```yaml
metrSource:
  dataCutoff: "2026-05-08"
  url: "https://metr.org/time-horizons/"

anchors:
  - { id: opus-4-6,       horizonMinutes: 718.8,  ci: [316.7, 3633.8], beyondReliable: false }
  - { id: mythos-preview, horizonMinutes: 1044.8, ci: [508.9, 3304.3], beyondReliable: true  }
  - { id: gpt-5-2,        horizonMinutes: 352.2,  ci: [198.1, 815.2],  beyondReliable: false }
  - { id: opus-4-5,       horizonMinutes: 293.0,  ci: [161.7, 623.7],  beyondReliable: false }
```

Все значения сняты из `benchmark_results_1_1.yaml` на metr.org, а не переписаны.
Схема это проверяет: каждый якорь обязан совпасть с точкой из `metrPoints` и
по дате, и по горизонту, `beyondReliable` обязан соответствовать границе в
шестнадцать часов, а точка не может быть новее среза данных.

**По умолчанию — не самый большой замер, а самый свежий из тех, за которые
METR ручается.** Это Claude Opus 4.6, 12,0 часа. Фронтирный Mythos Preview
(17,4 ч) доступен кнопкой «Use latest METR frontier» и сопровождается
предупреждением: он выше границы надёжности, а его доверительный интервал —
от 8,5 до 55 часов.

### Кодирование в ссылке

Индекс якоря занял биты 4–6 свободного полубайта во флагах. Версия кодека не
менялась, и это законно ровно при одном условии: **ноль означает прежнее
поведение**. В ссылках, выпущенных до этой правки, там нули, и они читаются
как якорь по умолчанию — то самое, чем модель пользовалась раньше. Отсюда
жёсткое требование: нулевой якорь в конфиге навсегда остаётся значением по
умолчанию, новые добавляются только в конец. Обратная совместимость закреплена
тестом на настоящей старой ссылке (`AR0FAggySwoUBDcAAA`).

Индекс за пределами списка отвергается целиком, как и неизвестная версия:
подставить якорь по умолчанию значило бы молча подменить единственное
измерение в модели.

## Что из этого вышло

Главное — не то, что ожидалось. Смена якоря почти ни на что не влияет:

| Якорь | Горизонт | Сингулярность | P(глобальная, 2100) |
|---|---|---|---|
| Claude Opus 4.5 | 4,9 ч | 2032-07 | 20,3% |
| GPT-5.2 | 5,9 ч | 2032-06 | 20,3% |
| Claude Opus 4.6 | 12,0 ч | 2031-12 | 20,1% |
| Mythos Preview | 17,4 ч | 2031-10 | 20,0% |

Измеренный горизонт различается в 3,6 раза, дата — на девять месяцев,
вероятность — на три десятых процентного пункта. Причина арифметическая: более
свежий замер и выше по вертикали, и правее по времени, и два сдвига гасят друг
друга. Время удвоения и допущения о риске двигают ответ на десятилетия.

Это ровно тезис сервиса, только теперь он подтверждён на том самом числе,
свежесть которого требовало ревью. Свежесть измерения — вопрос честности, а не
рычага, и так это и написано на странице.

## Заодно исправлено

`metrPoints` переписан целиком: пятнадцать точек, все помеченные METR как SOTA
начиная с GPT-4, все из одного среза TH1.1, `approx` больше нигде не `true`.
Базовое время удвоения приведено к точечной оценке METR для тренда с 2023 года:
131 → 129 дней (доверительный интервал 104–158). Подсказка ползунка называла
несуществующие числа — «196 дней с 2019, 131 с 2023, 89 с 2024»; у METR это
188 и 129, а оценки «с 2024» в файле нет вовсе.

Таблица под графиком показывала только первую точку METR в году и молча теряла
остальные — теперь показывает все.
